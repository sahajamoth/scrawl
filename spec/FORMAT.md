# Scrawl Format Specification

Version 1 — 2026-03-26

---

## Overview

Scrawl is a TOML-based diagram description format designed to be generated by large language models. It prioritizes token efficiency, structural predictability, and zero ambiguity over human ergonomics. A three-node diagram with two edges requires approximately 55 tokens — well within the budget of a single LLM response.

Coordinates are never specified. All positions are computed by the renderer from the graph topology and the declared layout direction. This eliminates an entire class of authoring errors and makes the format stable under model generation.

Rendering is deterministic. Given identical file content, the renderer always produces identical SVG output. This is achieved by deriving a random seed from the content hash of the canonicalized TOML string and passing it to rough.js. The handwritten aesthetic varies only when content changes.

### Design goals

- **Token efficiency.** Minimize tokens per diagram element without sacrificing machine readability.
- **LLM-first.** The format must be generatable by instruction-following models without examples, given only the 20-token schema hint in this document.
- **No coordinates.** Authors describe topology, not geometry.
- **Deterministic output.** Same input always yields same SVG.
- **Handwritten aesthetic.** rough.js renders all geometry with natural line variation seeded from content.
- **Strict validation.** Every structural error is caught at parse time, not render time.

### Non-goals

- Human hand-authoring ergonomics (use Mermaid for that)
- Round-trip editing of SVG back to scrawl
- Animation or interactivity
- Pixel-precise layout control

## File Format

| Property | Value |
|----------|-------|
| Extension | `.scrawl` |
| Encoding | UTF-8 (no BOM) |
| Base format | TOML 1.0 |
| Line endings | LF or CRLF (normalized on parse) |

A scrawl file is a valid TOML 1.0 document. Parsers must reject files that are not valid TOML before applying any scrawl-specific validation.

Unknown top-level keys must emit a warning and be ignored. They must not cause a parse failure. This allows forward-compatible extensions without breaking older renderers.

## Diagram Section `[d]`

The `[d]` table configures global diagram properties. It is optional; omitting it applies all defaults.

```toml
[d]
title = "optional title"   # string, optional — rendered above the diagram
dir   = "lr"               # layout direction (default: td)
theme = "rough"            # visual theme (default: rough)
```

### `title`

Type: string. Optional.

When present, the title is rendered in the Caveat font above the diagram area. No maximum length is enforced, but titles longer than 80 characters will wrap at renderer discretion.

### `dir`

Type: string. One of: `lr`, `td`, `rl`, `dt`, `radial`. Default: `td`.

Controls the primary axis along which auto-layout arranges nodes.

| Value | Name | Description |
|-------|------|-------------|
| `lr` | Left to right | Nodes flow left to right along the primary axis |
| `td` | Top to bottom | Nodes flow top to bottom along the primary axis (default) |
| `rl` | Right to left | Nodes flow right to left |
| `dt` | Bottom to top | Nodes flow bottom to top |
| `radial` | Radial | First node is centered; all others radiate outward |

An unknown `dir` value is a validation error.

### `theme`

Type: string. One of: `rough`, `clean`. Default: `rough`.

| Value | Description |
|-------|-------------|
| `rough` | All geometry rendered via rough.js with hand-drawn line variation |
| `clean` | Geometry rendered as precise SVG paths, Caveat font retained |

## Node Array `[[n]]`

Each `[[n]]` entry defines one node. Nodes are rendered in declaration order for z-ordering purposes, but layout position is determined solely by the graph topology and `dir`.

```toml
[[n]]
id = "a"        # required — unique identifier
l  = "Label"    # required — display label
s  = "b"        # shape code (default: b)
c  = "blue"     # fill color (optional)
```

### `id`

Type: string. Required. Must be unique across all nodes in the file.

Allowed characters: ASCII alphanumeric (`a-z`, `A-Z`, `0-9`), underscore (`_`), hyphen (`-`). No spaces. No leading hyphens.

Duplicate `id` values are a validation error.

### `l`

Type: string. Required.

The text label displayed inside the node. Use `\n` for explicit line breaks within the label. The renderer wraps text that exceeds the node width.

### `s`

Type: string. One of the shape codes below. Default: `b`.

| Code | Shape | Description |
|------|-------|-------------|
| `b` | Rectangle | Plain box with sharp corners |
| `r` | Rounded Rectangle | Box with rounded corners |
| `c` | Circle | Ellipse or circle; aspect ratio follows label size |
| `d` | Diamond | Decision node; rotated square |
| `y` | Cylinder | Database or storage node; top and bottom ellipses |
| `p` | Parallelogram | Input/output node; slanted sides |
| `h` | Hexagon | Process or preparation node; six sides |

An unknown shape code is a validation error.

### `c`

Type: string. Optional.

Accepted values: CSS named colors (e.g., `blue`, `tomato`, `steelblue`) or six-digit hex notation (`#rrggbb`). Three-digit hex shorthand (`#rgb`) is also accepted and expanded to six digits.

The color applies to the node fill. The renderer derives an appropriate stroke color and label contrast color automatically. When omitted, the renderer applies its default theme palette.

---

## Edge Array `[[e]]`

Each `[[e]]` entry defines one directed edge between two nodes.

```toml
[[e]]
f  = "a"       # from node id (required)
t  = "b"       # to node id (required)
l  = "label"   # edge label (optional)
st = "solid"   # line style (default: solid)
a  = "arrow"   # arrowhead style (default: arrow)
```

### `f` and `t`

Type: string. Both required.

Must reference the `id` of a declared node. Referencing a non-existent node id is a validation error.

Self-referencing edges (`f` equals `t`) are permitted and render as a loop.

### `l`

Type: string. Optional.

Label rendered along the edge midpoint. Short labels (under 30 characters) are preferred; longer labels may overlap adjacent edges in dense graphs.

### `st`

Type: string. One of: `solid`, `dashed`, `dotted`. Default: `solid`.

| Value | Description |
|-------|-------------|
| `solid` | Continuous line |
| `dashed` | Regular dash pattern |
| `dotted` | Dot pattern |

### `a`

Type: string. One of: `arrow`, `none`, `both`. Default: `arrow`.

| Value | Description |
|-------|-------------|
| `arrow` | Arrowhead at the `t` (target) node |
| `none` | No arrowheads; plain line |
| `both` | Arrowheads at both ends |

---

## Group Array `[[g]]`

Each `[[g]]` entry defines a visual grouping of nodes. Groups render as a lightly-filled background rectangle that encloses all member nodes. Groups do not affect layout — the layout engine positions nodes first, then groups are drawn to fit.

```toml
[[g]]
id    = "g1"
l     = "Group Label"        # optional
nodes = ["a", "b", "c"]     # node ids belonging to this group
```

### `id`

Type: string. Required. Must be unique among group ids (group ids and node ids occupy separate namespaces).

### `l`

Type: string. Optional. Label rendered at the top-left corner of the group rectangle.

### `nodes`

Type: array of strings. Required. Each element must be the `id` of a declared node. Referencing a non-existent node id is a validation error. An empty `nodes` array is a validation error.

Groups cannot nest. A node may not belong to more than one group.

---

## Layout Semantics

The layout engine operates on the directed graph formed by all nodes and edges. The `dir` value sets the primary axis for the layout algorithm (dagre for hierarchical directions; a radial algorithm for `radial`).

Nodes with no edges are positioned by the layout engine as isolated nodes and packed into available space near the main graph.

Multiple disconnected subgraphs are laid out independently, then packed together without overlap in the final SVG viewport.

The layout engine may add whitespace between nodes for readability. The exact padding values are implementation-defined but must remain consistent across renders of identical content (they are not seeded — only rough.js geometry is seeded).

Coordinates are computed values. They must never appear in `.scrawl` files.

## Rendering Contract

### Determinism

Identical `.scrawl` file content must always produce identical SVG output from the same renderer version. This property enables caching, diffing, and reliable embedding in version-controlled documentation.

### Seed derivation

1. Canonicalize the TOML: parse the file and re-serialize using a canonical key ordering (alphabetical at each level) with no trailing whitespace.
2. Compute xxhash32 of the UTF-8 bytes of the canonical string.
3. Interpret the result as a 32-bit unsigned integer.
4. Pass this integer as the `seed` option to the rough.js `RoughSVG` constructor.
5. Use the same seed for every rough.js draw call within the render.

### Font

The Caveat font (Google Fonts, Latin subset) is embedded as a base64-encoded WOFF2 data URI inside a `<style>` element in the SVG `<defs>` block. External font loading is explicitly forbidden — the SVG must be self-contained and renderable offline.

Font size defaults: node labels 14px, edge labels 12px, group labels 13px, diagram title 18px.

### Z-order

Elements are rendered in the following order (back to front):

1. Groups (filled background rectangles)
2. Edges (lines and arrowheads)
3. Nodes (shapes and labels)

Node labels are always visible above edges and group fills.

### SVG structure

```
<svg xmlns="http://www.w3.org/2000/svg" ...>
  <defs>
    <style>/* Caveat font, base64 WOFF2 */</style>
    <marker id="arrow"> ... </marker>
    <marker id="arrow-both"> ... </marker>
  </defs>
  <g class="scrawl-groups"> ... </g>
  <g class="scrawl-edges"> ... </g>
  <g class="scrawl-nodes"> ... </g>
</svg>
```

## Token Budget

The following table gives approximate token counts (OpenAI cl100k_base tokenizer) for complete, valid `.scrawl` files.

| Diagram | Nodes | Edges | Groups | Approx tokens |
|---------|-------|-------|--------|---------------|
| Minimal | 1 | 0 | 0 | ~15 |
| Simple | 3 | 2 | 0 | ~55 |
| Medium | 5 | 5 | 1 | ~100 |
| Complex | 10 | 12 | 2 | ~200 |

Token counts include TOML keys, string delimiters, newlines, and values. They exclude any system prompt overhead.

## Minimal LLM Prompt

The following 20-token schema hint is suitable for inclusion in LLM system prompts to enable scrawl generation without examples:

```
Use .scrawl TOML: [d] dir/title/theme. [[n]] id/l/s/c. [[e]] f/t/l/st/a. [[g]] id/l/nodes[].
```

Models that have seen this specification will generate valid scrawl from this hint alone. Models that have not seen it should be given one complete example alongside the hint.

## Versioning

The current format version is **1**. No explicit version key is required in v1 files.

Future breaking changes will increment the version. A v2 file must declare:

```toml
[d]
v = 2
```

v1 parsers encountering `v = 2` must emit a clear error: "This file requires a scrawl v2 parser."

The `v` key is reserved in `[d]` for version declarations. Parsers for v1 must treat `v = 1` as a no-op (accepted, ignored) and reject any other integer value.

## Error Handling

All errors below are validation errors. They must halt rendering and report the error with file location (line number where available) before producing any output.

| Condition | Error message pattern |
|-----------|----------------------|
| Duplicate node `id` | `Duplicate node id: "<id>"` |
| Edge `f` or `t` references unknown node | `Edge references unknown node id: "<id>"` |
| Group `nodes` references unknown node | `Group "<id>" references unknown node id: "<id>"` |
| Unknown shape code in `[[n]]` | `Unknown shape code: "<s>". Valid codes: b r c d y p h` |
| Unknown `dir` value in `[d]` | `Unknown dir value: "<dir>". Valid values: lr td rl dt radial` |
| Missing required `id` in `[[n]]` | `Node is missing required field: id` |
| Missing required `l` in `[[n]]` | `Node "<id>" is missing required field: l` |
| Missing required `f` in `[[e]]` | `Edge is missing required field: f` |
| Missing required `t` in `[[e]]` | `Edge is missing required field: t` |
| Missing required `nodes` in `[[g]]` | `Group "<id>" is missing required field: nodes` |
| Empty `nodes` array in `[[g]]` | `Group "<id>" has an empty nodes array` |
| Node belongs to multiple groups | `Node "<id>" belongs to multiple groups` |
| Unknown top-level key | Warning only: `Unknown top-level key: "<key>" (ignored)` |
| Invalid TOML | `TOML parse error: <upstream message>` |

## ABNF Grammar

The following Augmented Backus-Naur Form grammar describes the structure of a valid scrawl document at the semantic level (above raw TOML syntax). TOML tokenization rules apply at the lexical level.

```abnf
scrawl-doc     = [diagram-section] *node-entry *edge-entry *group-entry

diagram-section = "[d]" LF
                  *( diagram-field LF )

diagram-field  = title-field / dir-field / theme-field / version-field

title-field    = %s"title" SP "=" SP DQUOTE *char DQUOTE
dir-field      = %s"dir" SP "=" SP DQUOTE dir-value DQUOTE
theme-field    = %s"theme" SP "=" SP DQUOTE theme-value DQUOTE
version-field  = %s"v" SP "=" SP 1*DIGIT

dir-value      = %s"lr" / %s"td" / %s"rl" / %s"dt" / %s"radial"
theme-value    = %s"rough" / %s"clean"

node-entry     = "[[n]]" LF
                 id-field LF
                 label-field LF
                 [shape-field LF]
                 [color-field LF]

edge-entry     = "[[e]]" LF
                 from-field LF
                 to-field LF
                 [label-field LF]
                 [style-field LF]
                 [arrow-field LF]

group-entry    = "[[g]]" LF
                 id-field LF
                 [label-field LF]
                 nodes-field LF

id-field       = %s"id" SP "=" SP DQUOTE node-id DQUOTE
label-field    = %s"l" SP "=" SP DQUOTE *char DQUOTE
shape-field    = %s"s" SP "=" SP DQUOTE shape-code DQUOTE
color-field    = %s"c" SP "=" SP DQUOTE color-value DQUOTE
from-field     = %s"f" SP "=" SP DQUOTE node-id DQUOTE
to-field       = %s"t" SP "=" SP DQUOTE node-id DQUOTE
style-field    = %s"st" SP "=" SP DQUOTE style-value DQUOTE
arrow-field    = %s"a" SP "=" SP DQUOTE arrow-value DQUOTE
nodes-field    = %s"nodes" SP "=" SP "[" *( DQUOTE node-id DQUOTE "," SP ) DQUOTE node-id DQUOTE "]"

node-id        = 1*( ALPHA / DIGIT / "_" / "-" )
shape-code     = "b" / "r" / "c" / "d" / "y" / "p" / "h"
style-value    = %s"solid" / %s"dashed" / %s"dotted"
arrow-value    = %s"arrow" / %s"none" / %s"both"
color-value    = css-named-color / hex-color
hex-color      = "#" 3HEXDIG / "#" 6HEXDIG
css-named-color = 1*ALPHA

char           = %x20-21 / %x23-5B / %x5D-10FFFF / escape
escape         = "\" ( %x22 / %x5C / %x6E / %x72 / %x74 )

SP             = %x20
LF             = %x0A / %x0D %x0A
DQUOTE         = %x22
ALPHA          = %x41-5A / %x61-7A
DIGIT          = %x30-39
HEXDIG         = DIGIT / %x41-46 / %x61-66
```

Note: This grammar is a semantic overlay on TOML. The actual parser must first validate TOML 1.0 compliance, then apply scrawl-specific validation as described in the Error Handling section.

Initial release. Defines:

- `[d]` diagram section with `title`, `dir`, `theme`
- `[[n]]` node entries with `id`, `l`, `s`, `c`
